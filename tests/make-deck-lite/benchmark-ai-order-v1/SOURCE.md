# AIオーダー運用改善 — benchmark source

このファイルは `make-deck-lite` の PowerPoint Agent 再現度テスト用の入力資料です。

## 目的

AIオーダー導入後の運用状況を、役員・本部長向けに簡潔に共有し、次に改善すべき運用ポイントを整理する。

## 事実

- PoCは7店舗で実施した。
- 本稼働は39店舗へ拡大した。
- 導入前3か月の売変率は 5.24%。
- 導入後3か月の売変率は 5.81%。
- 導入前後差は +0.58pt。
- 発注修正あり率は 22.27%。
- 発注修正率と売変率変化の相関は r=0.39。
- この相関は因果関係を示すものではない。

## 運用上の観察

- 直納、セット、取り置きなど、通常ロジックだけでは扱いにくい例外商品がある。
- 棚割整備、Min/Max設定、週次発注など、店舗側の運用条件が結果に影響しうる。
- 前日修正には、数量丸め、軽微な数量変更、納品日まわりの手直し、AI推奨値との意図不明な乖離などが含まれる。
- 現状は修正理由が十分残らないため、どの修正が必要な運用補正で、どの修正が不要な手直しかを分離しにくい。

## 資料で伝えたいこと

- AIオーダーは導入店舗数の拡大段階から、運用品質を上げる段階へ移っている。
- 売変率は導入後に +0.58pt 悪化しているが、これをAIオーダーの因果効果とは断定しない。
- 修正あり率 22.27% は、人の介入が一定量残っていることを示す。
- 次は「修正理由を残す」「例外商品を定義する」「棚割・Min/Maxを整える」を優先したい。

## 禁止事項

- r=0.39 から「修正が売変悪化の原因」と断定しない。
- 根拠のない削減率、金額効果、ROIを追加しない。
- この資料にない店舗名・部門名・改善効果を作らない。
